เอกสารนี้ใช้ flow แบบ Map-based SOS Job Pool ตาม requirement ล่าสุด

ภาษา UI
- ผู้เยี่ยมชมเลือกภาษาได้จากหน้า Welcome และค่าจะถูกจำไว้ใน browser
- ระบบรองรับ English, Chinese, Thai, Spanish และ Arabic
- Arabic ใช้ทิศทางการอ่าน RTL
- ภาษา UI ไม่ใช่ภาษาที่ล่ามให้บริการ และไม่เปลี่ยนรายการภาษาในระบบ matching

Auth
- ผู้สมัครกรอกข้อมูลบังคับใน `/register` ได้แก่ ชื่อ อีเมล รหัสผ่าน เบอร์โทรศัพท์ และวันเดือนปีเกิด โดยวันเดือนปีเกิดแสดงเป็นลำดับ วัน เดือน ปี; ถ้าอีเมลซ้ำ ระบบแจ้งว่ามีผู้ใช้นี้แล้ว
- Supabase สร้างบัญชีใหม่ด้วย role `User` และเปิด session ให้ใช้งานได้ทันทีโดยไม่บังคับ email confirmation
- หลังสมัครหรือ Login ระบบตรวจ profile และ role ฝั่ง server ก่อนพาไป `/user`, `/interpreter`, `/manager` หรือ `/admin`
- `/login` แสดงฟอร์ม Login โดยตรง ส่วนหน้าแรกยังเปิด Login modal และ `/sign-in` ยัง redirect กลับหน้าแรกเพื่อเปิด modal
- Login ใช้ checkbox `จดจำฉัน` ซึ่งเริ่มต้นเป็นไม่เลือก; เมื่อเลือก session จะอยู่ต่อได้ไม่เกิน 15 วันนับจาก Login ครั้งนั้นแบบไม่ต่อ deadline จากการ refresh, เมื่อไม่เลือกใช้ session cookie ที่หมดอายุเมื่อปิด browser; ระบบไม่เก็บ password หรือ session token ใน `localStorage`
- Forgot password ตอบข้อความเดียวกันสำหรับอีเมลที่มีและไม่มีบัญชี และส่ง recovery link ผ่าน `/api/auth/callback`
- Recovery link ที่ผิดหรือหมดอายุพาไปหน้าขอลิงก์ใหม่ได้; เมื่อเปลี่ยนรหัสผ่านสำเร็จระบบปิด recovery session และพากลับ `/login`

กติกากลาง
- User สร้างคำขอความช่วยเหลือจากหน้า Welcome ได้ครั้งละหนึ่งคำขอที่ยังดำเนินการอยู่ หากมีคำขอหรืองานล่ามค้างอยู่ ระบบจะแจ้งเตือนและไม่ให้สร้างรายการใหม่
- Interpreter ที่ Approved เห็นเฉพาะหมุดที่ตรงกับภาษาและหมวดหมู่ความถนัด
- Interpreter กด Claim ได้ครั้งละหนึ่งงาน และไม่มีปุ่ม Reject งาน โดยกติกานี้ใช้ร่วมกับคำขอฝั่งผู้ขอของบัญชีเดียวกัน
- Interpreter สลับระหว่างโหมดให้ความช่วยเหลือและขอความช่วยเหลือภายในหน้า `/interpreter` เดียวได้แม้มีรายการค้างอยู่ หากกดสร้างคำขอหรือรับงานใหม่ ระบบแสดงป็อปอัปแจ้งเตือนและไม่บันทึกรายการใหม่
- ก่อน Claim แสดงเฉพาะชื่อสถานที่แบบกว้าง ๆ
- หลัง Claim User ต้องยืนยันล่ามก่อนจึงเปิดข้อมูลติดต่อและพิกัดจริงตามสิทธิ์
- ไม่มีระบบ Chat
- ผู้ใช้ทุก role ลบบัญชีถาวรจาก Profile Settings ได้เมื่อไม่มีคำขอ Open ที่ยังไม่หมดอายุหรืองาน Claimed/InProgress ระบบลบ Auth, profile, ไฟล์ใบสมัคร และข้อมูลที่ผูกกับบัญชีตาม foreign key แล้วล้าง session ใน browser

User (ผู้ขอความช่วยเหลือ)
หน้า                                      เชื่อมไปยัง
1. Welcome หลัง login (`/user`)          -> หน้าสร้างคำขอความช่วยเหลือ
2. สร้างคำขอ                              -> เลือกภาษา หมวดหมู่ รายละเอียด และตำแหน่ง
3. คำขอที่สร้างแล้ว                       -> รายละเอียดคำขอ แก้ไขได้ขณะ Open หรือ Claimed ก่อนล่ามเริ่มงาน และติดตามสถานะ
4. หลัง Interpreter Claim                 -> ดูโปรไฟล์ล่ามและยืนยันล่าม
5. หลังยืนยันล่าม                         -> ดูข้อมูลติดต่อ พิกัดจริง และแผนที่ตำแหน่งแบบเรียลไทม์ของทั้งสองฝ่ายตามสิทธิ์
6. คำขอที่กำลังดำเนินการ                  -> ติดตามตำแหน่งอัตโนมัติขณะเปิดหน้า ยืนยันเริ่ม/จบงาน ยกเลิก และดู Timeline
7. งาน Completed                          -> ส่ง Review ให้ Interpreter
8. ประวัติคำขอ                            -> เปิดดูคำขอเดิมแบบ read-only
9. สมัครเป็น Interpreter                  -> แบบฟอร์มสมัครและหน้าสถานะใบสมัคร

Interpreter (ล่ามจิตอาสา)
หน้า                                      เชื่อมไปยัง
0. Welcome หลัง login (`/interpreter`)   -> งานที่ตรงความสามารถและงานที่รับไว้
1. สมัครล่าม                              -> กรอกภาษา หมวดหมู่ และรายละเอียดประสบการณ์
2. สถานะใบสมัคร                           -> Pending / Approved / Rejected
3. Dashboard แผนที่                       -> เห็นหมุด Open ที่ตรงความสามารถและระยะทางที่เลือก
4. รายละเอียดหมุด                         -> ดูข้อมูลแบบคร่าว ๆ และกด Claim
5. หลัง Claim                              -> รอ User ยืนยันล่าม และเข้าหน้ารายละเอียดคำขอ
6. งาน Claimed                             -> แชร์ตำแหน่ง ดูแผนที่สองฝ่ายเมื่อ User ยืนยัน และกดเริ่มงาน
7. งาน InProgress                          -> ยืนยันจบงานหรือยกเลิก
8. งาน Completed                           -> ดูประวัติงานและคะแนนที่ได้รับ

สถานะใบสมัคร
- Pending: ยังใช้ role User และยังรับงานไม่ได้
- Approved: ระบบเปลี่ยน role เป็น Interpreter
- Rejected: ยังคง role User และแสดงเหตุผล

Manager (ผู้ประสานงาน)
หน้า                                      เชื่อมไปยัง
1. Manager Console                        -> คิวใบสมัครและงานที่ได้รับมอบหมาย
2. รายการใบสมัคร                          -> กรองภาษา หมวดหมู่ และสถานะ
3. รายละเอียดใบสมัคร                      -> Approve หรือ Reject พร้อมเหตุผล
4. Help Requests                           -> ตอบคำร้องและเปลี่ยนสถานะเป็น Resolved
5. Reports                                 -> ตรวจสอบและส่งต่อ Admin หากเกินสิทธิ์
6. ข้อมูลคำขอ/ผู้ใช้                       -> เห็นตาม permission ที่ได้รับ

Manager ไม่สามารถเปลี่ยน role, Lock/Unlock หรือดำเนินการที่เกิน permission ของตนเอง

Admin
หน้า                                      เชื่อมไปยัง
1. Admin Dashboard                         -> ภาพรวมผู้ใช้ คำขอ และสถานะระบบ
2. รายชื่อผู้ใช้                           -> ค้นหาและกรองตาม role
3. รายละเอียดผู้ใช้                        -> แก้ไขข้อมูลและเปลี่ยน role
4. ข้อมูลคำขอและผู้ใช้                      -> เห็นข้อมูลทั้งหมดตามสิทธิ์ Admin
5. Audit Log                               -> ดู action ของ Manager และ Admin
6. Lock/Unlock                             -> อยู่ใน MVP และต้องตรวจสิทธิ์พร้อมบันทึก Audit Log

วงจรสถานะคำขอ

Open -> Claimed -> InProgress -> Completed
  |        |           |
  |        |           +-> Cancelled เมื่อ Interpreter ยกเลิกหลังเริ่มงาน
  |        +-> Open เมื่อ Interpreter ยกเลิกก่อนเริ่มงานและยังไม่หมดอายุ
  +-> Expired เมื่อหมดอายุ
  +-> Cancelled เมื่อ User ยกเลิกก่อน Completed

ประเภทเวลา
- Immediate: แสดงระดับความเร่งด่วน เช่น “ต้องการความช่วยเหลือภายใน 15 นาที” และหมดอายุ 30 นาทีหลังสร้าง
- Scheduled: แสดงทันทีหลังสร้าง เลือกเวลานัดได้ตั้งแต่วันถัดไปตามปฏิทินโดยไม่จำกัดวันสูงสุด และหมดอายุเมื่อถึงเวลานัดหมาย
